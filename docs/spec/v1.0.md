# Spec v1.0

Status: approved 2026-11-24. Grill record: [2026-11-24-settlein-v0.1](../grill/2026-11-24-settlein-v0.1.md).

## Goal

After v1.0 a person with a new Mac opens settlein.dev, ticks the apps they want and downloads Settlein. Settlein shows the list, waits for approval, then downloads, verifies and installs every app with no Terminal and no visits to vendor websites. Settlein also removes the apps it installed, with their leftovers.

## How to read a claim

Each claim is one testable sentence.

- "I said" quotes the grill record. It holds the owner's own words, or `Q<n>` and the option the owner picked.
- "Proof" says how the claim is shown to work.
- "Assumes" lists the assumption IDs the claim depends on. The table under "Spec assumptions" defines them.

QA proves each claim in a real session and posts the evidence in one comment on the issue PR, with `gh pr comment --attach`. QA writes no evidence folder in the repo.

## F0 Catalog

**C1.** The Settlein catalog file shall hold exactly the apps in the "Catalog list" section of this spec.
- I said: "lets do a currated list of mac apps based on ninite and macapps.link please. i will check and modify and approve the final list"
- Proof: QA fetches the catalog file from settlein.dev and compares its app names with the "Catalog list" section. The two lists match.
- Assumes: S14

**C2.** A scheduled job shall rebuild the Settlein catalog file from Homebrew Cask data once a day.
- I said: Q26, Settlein publishes its own catalog file, rebuilt daily from Homebrew.
- Proof: QA opens the job's run history in GitHub Actions and shows two runs on consecutive days. QA shows that a catalog entry's version equals the version in `https://formulae.brew.sh/api/cask/<token>.json` after a run.
- Assumes: S12

**C3.** Each catalog entry shall hold the app's name, category, download link, version, installer type and leftover paths, and its checksum when Homebrew gives one.
- I said: Q3, Curated list on Homebrew data.
- Proof: QA prints three entries from the catalog file, one copy app, one pkg app and one app with no checksum. Each shows every field.
- Assumes: S7, S12

**C4.** The catalog shall hold no app that exists only on the Mac App Store.
- I said: Q7 and Q22, Keep them out.
- Proof: QA checks that every catalog entry has a vendor download link from outside the Mac App Store.

**C5.** The Settlein app shall read catalog data only from settlein.dev.
- I said: Q26, The app never calls Homebrew.
- Proof: QA records the app's network requests during one install run. The catalog request goes to settlein.dev and no request goes to `formulae.brew.sh`.

## F3 Install

**C18.** Settlein shall download nothing from the selection until the person approves the confirmation screen.
- I said: "that app double checks with you that you want those apps and then it downloads them all"
- Proof: QA records network requests while the confirmation screen is open and shows no vendor download starts. QA clicks approve and the downloads start.

**C19.** After the person approves, Settlein shall download and install every app in the selection without the person opening a vendor website or Terminal.
- I said: "everytime i receive a new computer (a mac specificially) i have to go to multiple websites."
- Proof: QA approves a selection of five copy apps. All five appear in the Applications folder and open. QA opened no browser tab and no Terminal during the run.

**C20.** Settlein shall install a copy app into `/Applications` for an admin user and into `~/Applications` for a standard user.
- I said: Q27, Admin users install to `/Applications`. Standard users install to `~/Applications`.
- Proof: QA installs one app as an admin user and one as a standard user, then lists both folders. No password prompt appears in either run.
- Assumes: S4, S15

**C21.** For a pkg app, Settlein shall download and verify the installer, then open it in Apple's Installer for the person.
- I said: Q6, Copy apps, and open .pkg files for the person.
- Proof: QA selects one pkg app. Apple's Installer opens with that package after Settlein reports it verified. Settlein shows no password prompt of its own.

**C22.** Settlein shall refuse to install a download that lacks a valid Developer ID signature or Apple notarization, and shall name the app and the reason.
- I said: Q16, Apple signature always, checksum when present.
- Proof: QA points a test catalog entry at an unsigned app. Settlein reports the refusal for that app and the Applications folder does not hold it.
- Assumes: S5

**C23.** When a catalog entry has a checksum, Settlein shall refuse to install a download whose SHA-256 differs from it, and shall name the app and the reason.
- I said: Q16, Apple signature always, checksum when present.
- Proof: QA changes one checksum in a test catalog. Settlein reports the mismatch for that app and does not install it. The other apps in the selection install.

**C24.** Settlein shall keep the quarantine attribute on every app it installs.
- I said: Q16, Apple signature always, checksum when present. [ADR-0011](../adr/0011-signature-always-checksum-when-present.md) records that Gatekeeper checks each app again on first open.
- Proof: QA runs `xattr -p com.apple.quarantine` on an app Settlein installed. The command prints a value.
- Assumes: S6

**C25.** When a selected app is already on the Mac, Settlein shall show it as already installed on the confirmation screen and shall leave it unchanged.
- I said: Q19, Skip it and say so.
- Proof: QA selects Google Chrome on a Mac that has it. The confirmation screen marks it as already installed. The bundle's modification date is the same after the run.

**C26.** Settlein shall run on Apple silicon Macs with macOS 27 and macOS 26.
- I said: Q15, Apple silicon, current macOS and one before.
- Proof: QA runs the install flow once on macOS 27 and once on macOS 26.
- Assumes: S15

**C27.** The Settlein app shall send no data about the person or the Mac to any server.
- I said: "web analytics but privacy first only on the website."
- Proof: QA records the app's network requests during an install and an uninstall. The only requests are the catalog fetch, the update check and vendor downloads, and none carries an identifier.

## F4 Uninstall

**C29.** When the person uninstalls a copy app, Settlein shall remove the app bundle and every leftover path the catalog lists for it.
- I said: Q4, Apps Settlein installed, with leftovers.

- Assumes: S7, S8

**C30.** When the person uninstalls a pkg app, Settlein shall ask for the admin password once through a macOS prompt and shall then remove the app's system files as well as its bundle and leftovers.
- I said: Q13, Ask for the admin password at uninstall.
- Proof: QA installs one pkg app, uninstalls it and enters the password in one prompt. QA lists each path the catalog names for that app, including paths under `/Library`. None exists.

**C31.** During an uninstall, Settlein shall delete only paths the catalog lists for that app.

- Proof: QA snapshots `~/Library` and `/Library` file lists before and after one uninstall. Every removed path is in the catalog entry for that app.

## Out of scope

Settlein never lists Mac App Store apps ([ADR-0017](../adr/0017-no-mac-app-store-apps.md)). v1.0 also leaves out updating installed apps, Intel Macs, accounts and unattended pkg installs. Updating installed apps and Intel Macs can come in a future version (Q37).

## Spec assumptions

| ID | Assumption | For | Against |
|----|------------|-----|---------|
| S1 | Safari and Chrome on macOS 27 keep the selection on the downloaded Settlein file, in its file name or in its `kMDItemWhereFroms` attribute. Unchecked. | A scout found that Chrome kept a query string on 1 of 5 downloads in `~/Downloads`, and that 5 of 6 file names matched the URL's last path segment. | The sample held no Safari download with a query string, and Safari unpacks a zip and leaves no origin attribute on the app inside. Only a spike with a test download settles it. |
| S2 | The Settlein app can find and read its own downloaded file when the person opens it from a mounted disk image or from the Downloads folder. Unchecked. | An app that is not sandboxed can ask macOS which image file a mounted volume came from. | Gatekeeper may run the app from a random read-only path, and the two unpacked apps in `~/Downloads` carried no origin attribute. Only the spike settles it. |
| S3 | A web page can open an installed Mac app through a custom URL scheme. Checked, scout report (`plutil` shows the `claude-cli` scheme registered by an app in `~/Applications`). | Mac apps declare schemes in `CFBundleURLTypes`, and browsers pass matching links to them. | Safari and Chrome ask the person to allow the first open, which adds one click. |
| S4 | An admin user can copy an app into `/Applications` with no password, and a standard user can write to `~/Applications`. Checked, scout report (`ls -ld /Applications` prints `drwxrwxr-x root admin`, and `test -w` prints `writable` for the owner). | The folder's group is `admin` with write permission. | The standard-user half was not run, because this Mac's only tested account is an admin. |
| S5 | Settlein can check a downloaded app's Developer ID signature and notarization before it installs the app. Checked, scout report (`codesign -v -R="notarized"` exits 0 and `spctl -a -vv` prints `source=Notarized Developer ID` for Spotify). | Apple's TN3127 documents the same check through the Security framework. | A forum report says the `notarized` requirement fails with no reason when Apple revokes a ticket, so the error text may be vague. |
| S6 | An app that is not sandboxed can set the quarantine attribute on files it downloads. Checked, researcher report (Apple forum thread 706442 names `quarantinePropertiesKey`). | Apple's engineers name the supported API. | Vendor installers differ. The scout found quarantine on Spotify and none on Google Chrome on this Mac. |
| S7 | Homebrew's `zap` and `uninstall` data lists the leftover paths for every app in the catalog list. Checked, catalog researcher report (all 44 casks have a `zap` stanza, and all 6 pkg casks list `pkgutil` in `uninstall`). | The researcher read both stanzas in Firefox's cask, and Homebrew requires `uninstall` for every pkg cask. | `zap` is optional and hand-written, so some apps may list few paths or none. A stanza can exist and still miss paths, so QA for C29 and C30 tests it per app. |
| S8 | Settlein can remove an app bundle it installed without the person granting the App Management permission in System Settings. Unchecked. | Settlein wrote the bundle itself, and an admin user owns it. | macOS 13 and later guard other developers' bundles, Apple offers no API to request the permission, and no source the scout found says an installer is exempt. If this is false, C29 needs a one-time step in System Settings. |
| S9 | Settlein can run a removal as root after one macOS password prompt, with no helper installed in advance. Checked, scout report (Apple TN2065: `with administrator privileges` "runs the command as the root user", and `/usr/bin/osascript` exists). | The mechanism ships with macOS. | TN2065 is an old note, and Apple may steer new apps to a registered helper. A standard user has no admin password to type. |
| S10 | The Apple Developer Program gives the owner a Developer ID certificate and notarization for 99 US dollars a year. Checked, researcher report (developer.apple.com/programs and the notarization page). | Apple states both on its own pages. | Enrolment can take days, and the release cannot ship before it completes. |
| S11 | Sparkle 2 updates a notarized Developer ID app on macOS 27 and signs updates with an EdDSA key. Checked in part, scout report (release 2.10.1 dated 2026-10-25, and the docs name EdDSA). | The project released a version one month ago. | The documentation page states no minimum macOS version, so macOS 27 support is not confirmed in writing. |
| S12 | Homebrew's public JSON API gives the download link, version, checksum and artifacts for each cask, and Settlein may use it in a free product. Checked in part, researcher report (`firefox.json` holds the fields, and the repos are BSD 2-Clause). | The fields exist and the source repos carry a permissive licence. | No page states terms for the API data itself. |
| S13 | Cloudflare Web Analytics counts visits without setting a cookie. Unchecked. | Cloudflare markets it as analytics "without compromising user privacy". | The two Cloudflare pages the scout read do not mention cookies. QA for C13 settles it by reading the browser's cookie store. |
| S14 | Every app in the "Catalog list" section has a Homebrew cask that is live and supports Apple silicon. Checked, catalog researcher report (each cask JSON read on 2026-11-24 through a summarising fetch tool). | The catalog researcher fetches each cask's JSON before an app joins the list. | A vendor can drop an app or a cask can be disabled after the list is approved. |
| S15 | QA can use a second macOS user account, a standard user account and a Mac or virtual machine with macOS 26. Unchecked. | macOS creates user accounts in System Settings, and Apple silicon Macs can run macOS virtual machines. | Only the owner can say which machines exist. Without macOS 26, C26 can be proved on macOS 27 only. |
