# Spec v1.0

Status: approved 2026-11-25, amendment 2 of the spec approved 2026-11-24. Grill records: [2026-11-24-settlein-v0.1](../grill/2026-11-24-settlein-v0.1.md) and [2026-11-25-design-handoff-v2](../grill/2026-11-25-design-handoff-v2.md).

## Goal

After v1.0 a person with a new Mac opens settlein.dev, picks apps in the full-screen picker and downloads SettleIn. SettleIn opens and at once downloads, verifies and installs every picked app, with no Terminal and no visits to vendor websites. SettleIn also lets the person pick more apps inside the app, and moves the apps it installed to the Trash with their leftovers.

## How to read a claim

Each claim is one testable sentence.

- "I said" quotes a grill record. It holds the owner's own words, or `Q<n>` and the option the owner picked. "D<n>" names a decision in the design handoff's `DECISIONS.md`, which the 2026-11-25 grill adopted.
- "Proof" says how the claim is shown to work.
- "Assumes" lists the assumption IDs the claim depends on. The table under "Spec assumptions" defines them.

Claim numbers do not change between amendments. A removed claim keeps its number with the word "Removed" and the reason.

The design lives in `docs/design/` ([ADR-0033](../adr/0033-final-design-handoff-replaces-the-figma-plan.md)). The screenshots named in Proof lines stay in `~/Downloads/SettleIn-handoff.zip` under `SettleIn-handoff/screenshots/`.

QA proves each claim in a real session and posts the evidence in one comment on the issue PR, with `gh pr comment --attach`. QA writes no evidence folder in the repo.

## Spec assumptions

| ID | Assumption | For | Against |
|----|------------|-----|---------|
| S1 | Safari and Chrome on macOS 27 keep the selection on the downloaded `SettleIn.dmg` in its `kMDItemWhereFroms` attribute. The file name carries no selection (ADR-0018). Unchecked. | A scout found that Chrome kept a query string on 1 of 5 downloads in `~/Downloads`, and that 5 of 6 file names matched the URL's last path segment. | The sample held no Safari download with a query string, and Safari unpacks a zip and leaves no origin attribute on the app inside. Only a spike with a test download settles it. |
| S2 | The SettleIn app can find and read its own downloaded file when the person opens it from a mounted disk image or from the Downloads folder. Unchecked. | An app that is not sandboxed can ask macOS which image file a mounted volume came from. | Gatekeeper may run the app from a random read-only path, and the two unpacked apps in `~/Downloads` carried no origin attribute. Only the spike settles it. |
| S3 | A web page can open an installed Mac app through a custom URL scheme. Checked, scout report (`plutil` shows a custom scheme registered by an installed app). | Mac apps declare schemes in `CFBundleURLTypes`, and browsers pass matching links to them. | Safari and Chrome ask the person to allow the first open, which adds one click. |
| S4 | An admin user can copy an app into `/Applications` with no password, and a standard user can write to `~/Applications`. Checked, scout report (`ls -ld /Applications` prints `drwxrwxr-x root admin`, and `test -w` prints `writable` for the owner). | The folder's group is `admin` with write permission. | The standard-user half was not run, because this Mac's only tested account is an admin. |
| S5 | SettleIn can check a downloaded app's Developer ID signature and notarization before it installs the app. Checked, scout report (`codesign -v -R="notarized"` exits 0 and `spctl -a -vv` prints `source=Notarized Developer ID` for an installed app). | Apple's TN3127 documents the same check through the Security framework. | A forum report says the `notarized` requirement fails with no reason when Apple revokes a ticket, so the error text may be vague. |
| S6 | An app that is not sandboxed can set the quarantine attribute on files it downloads. Checked, researcher report (Apple forum thread 706442 names `quarantinePropertiesKey`). | Apple's engineers name the supported API. | Vendor installers differ. The scout found quarantine on one installed app and none on another. |
| S7 | Homebrew's `zap` and `uninstall` data lists the leftover paths for every app in the catalog list. Checked, catalog researcher report (all 44 casks have a `zap` stanza, and all 6 pkg casks list `pkgutil` in `uninstall`). | The researcher read both stanzas in Firefox's cask, and Homebrew requires `uninstall` for every pkg cask. | `zap` is optional and hand-written, so some apps may list few paths or none. A stanza can exist and still miss paths, so QA for C29 and C30 tests it per app. |
| S8 | SettleIn can move an app bundle it installed without the person granting the App Management permission in System Settings. Unchecked. | SettleIn wrote the bundle itself, and an admin user owns it. | macOS 13 and later guard other developers' bundles, Apple offers no API to request the permission, and no source the scout found says an installer is exempt. If this is false, C29 needs a one-time step in System Settings. |
| S9 | SettleIn can run a removal as root after one macOS password prompt, with no helper installed in advance. Checked, scout report (Apple TN2065: `with administrator privileges` "runs the command as the root user", and `/usr/bin/osascript` exists). | The mechanism ships with macOS. | TN2065 is an old note, and Apple may steer new apps to a registered helper. A standard user has no admin password to type. |
| S10 | The Apple Developer Program gives the owner a Developer ID certificate and notarization for 99 US dollars a year. Checked, researcher report (developer.apple.com/programs and the notarization page). | Apple states both on its own pages. | Enrolment can take days, and the release cannot ship before it completes. |
| S11 | Sparkle 2 updates a notarized Developer ID app on macOS 27 and signs updates with an EdDSA key.
