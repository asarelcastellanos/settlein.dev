Decisions

Each card is a decision with real options. The chosen option is marked and has a heavy border. Cards run in number order.

ADR-0033. Final design handoff replaces the Figma plan

  • ChosenCommit the handoff without the screenshots to docs/design/ and leave the screenshots in the owner's Downloads
  • ConsideredCommit the whole handoff, screenshots included
  • ConsideredAsk the designer to redo the handoff in Figma

WhyThe owner said everything except screenshots, so clones stay small and the text, tokens and assets live next to the code.

ADR-0033

ADR-0034. Install starts without a confirmation screen

  • ChosenStart installing as soon as SettleIn opens with a selection, with Cancel and Change selection always on the Installing screen
  • ConsideredKeep the confirmation screen from C18
  • ConsideredShow the selection for a few seconds with a countdown, then start

WhyThe owner decided it in the handoff, and the signature, notarization and checksum checks still refuse bad downloads.

ADR-0034

ADR-0035. Pick apps inside the app

  • ChosenAn in-app picker, with launch logic: a selection goes to Installing, no selection and nothing installed goes to Pick apps, anything else goes to the installed list
  • ConsideredKeep the browser hand-off from C16 and ADR-0027

WhyThe owner decided it in the handoff, so a person can add apps later without the website.

ADR-0035

ADR-0036. Uninstall moves files to the Trash

  • ChosenMove the bundle and leftovers to the person's Trash
  • ConsideredDelete them permanently

WhyThe owner chose it, so a person who removed the wrong app can put it back from the Trash.

ADR-0036

ADR-0037. Standard users cannot remove pkg apps

  • ChosenShow a panel saying an administrator must remove the app, with no password prompt
  • ConsideredShow the macOS prompt anyway, so an administrator can type their name and password

WhyThe owner chose it, so a standard user never sees a prompt they cannot complete.

ADR-0037

ADR-0038. Rename the app to SettleIn with a capital I

  • ChosenRename the display name, product name, disk image and bundle ID, with bundle ID dev.settlein.SettleIn
  • ConsideredRename only the display name and keep dev.settlein.Settlein

WhyThe owner chose it, and nothing has shipped yet, so the name, file names and identifier can match before a bundle ID change would break updates.

ADR-0038

ADR-0039. Website and app are light only

  • ChosenLight only, with the Mac app forced to light through .preferredColorScheme(.light) on the root view
  • ConsideredFollow the system appearance with the reserved dark values

WhyThe owner decided it in the handoff, so each screen is built and checked once.

Risks

  • The download cannot carry the selection (S1, S2). C15 fails as written. The owner picks a fallback in a new ADR that supersedes ADR-0018. The likely fallback is a plain download followed by the settlein:// link, which costs one extra click.
  • macOS requires the App Management permission to move an app to the Trash (S8, S16). C29 needs a new claim for a one-time step in System Settings.
  • The scroll-story zoom stutters on slow Macs or phones. C35 fails on those devices. The ui-builder uses transforms only and honours Reduce Motion, and QA records it at 1440 and 375 px.
  • The picker exists twice, in Astro and SwiftUI. The two drift apart. Both read the same catalog file and the same tokens from docs/design/tokens/.
  • The rename misses a path. A script or Info.plist still says Settlein, and C57 fails. The reviewer greps for Settlein outside settlein.dev.
  • Pixel matching takes many rounds (C45, C53). Review loops run long. The design-critic compares against the screenshots once per screen, and live content differences are allowed.
  • A link someone else sent starts installing at once (ADR-0034). The person sees the installs begin and can Cancel. Every app is still a catalog app that passes the checks.
  • The handoff screenshots live only in the owner's Downloads. Agents cannot check a screen if the zip moves. Agents read it from ~/Downloads/SettleIn-handoff.zip and the owner keeps it there until release.
  • No macOS 26 machine exists. C26 is proved in CI on macos-26 with no clicked-through install, unless the owner sets up a VM.
  • The Sparkle key is lost. Existing installs can never update again. The owner keeps a backup.
