## Build order

1. **Logic merge.** Branches `feature/website`, `feature/install` and `feature/distribution`. Covers C5, C7, C8, C11 and C20 to C24. Depends on nothing. Each branch gets a reviewer pass and QA on its logic claims, then merges into `release/v1.0`. Issues #9 and #10 close or move their open UI claims to the redesign issues.
2. **Design system and rename.** Branch `feature/design-system`. Covers C57. Depends on Logic merge. A mechanic copies the handoff into `docs/design/`. A coder adds the tokens to the website and the app, adds the assets, and renames Settlein to SettleIn in code, scripts and docs.
3. **Website design.** Branch `feature/website-design`. Covers C6, C9, C10, C12 and C35 to C45. Depends on Design system.
4. **App design.** Branch `feature/app-design`. Covers C16, C19, C25 and C46 to C54. Depends on Design system. It removes the confirmation screen built in #9.
5. **Handoff.** Branch `feature/handoff`, created again from `release/v1.0`. Covers C15 and C17. Depends on Website design and App design. It serves `/dl` as a static disk image with a `_headers` rule.
6. **Uninstall.** Branch `feature/uninstall`, created again from `release/v1.0`. Covers C28 to C31 and C56. Depends on App design.
7. **Distribution.** Branch `feature/distribution-2`. Covers C26, C32, C33 and C55. Depends on Design system and App design. It adds Sparkle, the disk image window and a `macos-26` CI build.
8. **Deploy.** Issue #8. Covers C13 and C14. Depends on the owner merging `release/v1.0` into main.

Steps 3, 4 and 6 can run side by side once step 2 merges. Each feature branch comes from `release/v1.0`. Each issue branch comes from its feature branch. Only `release/v1.0` merges into main, after the owner approves the review package.

## Risks

- **The download cannot carry the selection (S1, S2).** C15 fails as written. The owner picks a fallback in a new ADR that supersedes ADR-0018. The likely fallback is a plain download followed by the `settlein://` link, which costs one extra click.
- **macOS requires the App Management permission to move an app to the Trash (S8, S16).** C29 needs a new claim for a one-time step in System Settings.
- **The scroll-story zoom stutters on slow Macs or phones.** C35 fails on those devices. The ui-builder uses transforms only and honours Reduce Motion, and QA records it at 1440 and 375 px.
- **The picker exists twice, in Astro and SwiftUI.** The two drift apart. Both read the same catalog file and the same tokens from `docs/design/tokens/`.
- **The rename misses a path.** A script or Info.plist still says Settlein, and C57 fails. The reviewer greps for `Settlein` outside `settlein.dev`.
- **Pixel matching takes many rounds (C45, C53).** Review loops run long. The design-critic compares against the screenshots once per screen, and live content differences are allowed.
- **A link someone else sent starts installing at once (ADR-0034).** The person sees the installs begin and can Cancel. Every app is still a catalog app that passes the checks.
- **The handoff screenshots live only in the owner's Downloads.** Agents cannot check a screen if the zip moves. Agents read it from `~/Downloads/SettleIn-handoff.zip` and the owner keeps it there until release.
- **No macOS 26 machine exists.** C26 is proved in CI on `macos-26` with no clicked-through install, unless the owner sets up a VM.
- **The Sparkle key is lost.** Existing installs can never update again. The owner keeps a backup.
