# Plan v1.0

Status: approved 2026-11-24. Spec: [v1.0](../spec/v1.0.md). Grill record: [2026-11-24-settlein-v0.1](../grill/2026-11-24-settlein-v0.1.md).

No code is written in the planning session. The owner ends the session once this plan is stored. Building starts in a later session with step 1 of the build order.

## What it adds

| Part | What it is | Claims |
|---|---|---|
| Repository | One public GitHub repo named `settlein.dev` with an MIT licence, the branch flow and the checks. | C34 |
| Test build | A throwaway signed app and a test download page. It settles assumptions S1, S2 and S8 before the real features depend on them. | none |
| Catalog | A catalog file with the 44 approved apps, and a daily job that rebuilds it from Homebrew Cask data. | C1, C2, C3, C4 |
| Website | One Astro page on Cloudflare Pages at settlein.dev. It shows the catalog, keeps ticked apps in the page address and starts the download. | C6 to C14 |
| Mac app, install | A Swift and SwiftUI app. It shows the confirmation screen, downloads, verifies and installs copy apps, and opens pkg installers. | C5, C18 to C27 |
| Handoff | The download that carries the selection, and the `settlein://` link for a Mac that already has Settlein. | C15, C16, C17 |
| Mac app, uninstall | The list of apps Settlein installed and their removal with leftovers. Pkg apps ask for the admin password. | C28 to C31 |
| Distribution | Developer ID signing, notarization, the release build and Sparkle updates. | C32, C33 |

## Build order

1. **Foundation.** Branch `feature/foundation`. Covers C34. Depends on nothing. Creates the repo, the licence, `release/v1.0`, and the comment and skill checks.
2. **Test build.** Branch `feature/test-build`. Covers no claim. Depends on Foundation. It downloads a signed test app in Safari and in Chrome and reports whether the app can read the selection from its file name or from `kMDItemWhereFroms` (S1, S2). It also installs and removes one app to see whether macOS asks for the App Management permission (S8). The owner reads the result before step 5 starts.
3. **Catalog.** Branch `feature/catalog`. Covers C1 to C4. Depends on Foundation.
4. **Website.** Branch `feature/website`. Covers C6 to C14. Depends on Catalog.
5. **Install.** Branch `feature/install`. Covers C5 and C18 to C27. Depends on Catalog.
6. **Handoff.** Branch `feature/handoff`. Covers C15 to C17. Depends on Test build, Website and Install.
7. **Uninstall.** Branch `feature/uninstall`. Covers C28 to C31. Depends on Install and Test build.
8. **Distribution.** Branch `feature/distribution`. Covers C32 and C33. Depends on Install.

Each feature branch comes from `release/v1.0`. Each issue branch comes from its feature branch. Only `release/v1.0` merges into main, after the owner approves the review package.

## Risks

- **The download cannot carry the selection (S1, S2).** C15 fails as written. The owner then picks a fallback in a new ADR that supersedes ADR-0002. The likely fallback is a plain download followed by the `settlein://` link, which costs one extra click.
- **macOS requires the App Management permission to remove an app (S8).** C29 needs a new claim for a one-time step in System Settings, and the uninstall screen must guide the person through it.
- **Apple enrolment takes days.** The test build and every signed build wait for it. Catalog and Website can proceed meanwhile.
- **Homebrew changes its JSON format or states terms that forbid reuse.** The daily job fails or the catalog needs a new source. The site and the app keep working from the last good catalog file.
- **A catalog fact is wrong.** The researcher read each cask through a summarising tool. The catalog job reads the raw JSON and must refuse an entry that breaks the rules, and QA installs every one of the 44 apps.
- **A vendor releases a new version before the daily job runs.** The checksum fails and that app does not install until the next run. The app must name the reason so the person can retry later.
- **Leftover data misses paths or names a wrong one.** A miss leaves files behind. A wrong path under the root step could delete system files. C31 limits deletion to listed paths, and each pkg entry's paths get a review before release.
- **A pkg install is cancelled in Apple's Installer.** Settlein cannot see the outcome directly and must check for the app afterwards.
- **The Sparkle key is lost.** Existing installs can never update again. The owner keeps a backup.
- **No macOS 26 machine exists.** C26 is proved on macOS 27 only, and the spec must say so.
